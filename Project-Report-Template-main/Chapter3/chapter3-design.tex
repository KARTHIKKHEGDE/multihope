\chapter{System Design and Architecture}

The QuantumHop system is designed as a two-tier, peer-to-peer secure communication platform. The backend tier, implemented in Python, handles all cryptographic operations, socket communication, peer discovery, attack detection, and event logging. The frontend tier, implemented in React, provides a real-time dashboard for message composition, peer management, inbox display, and attack alerts. The two tiers communicate through a local Flask REST API that bridges the browser to the underlying socket layer.

\section{BB84 Protocol Design}

The BB84 QKD simulation is the cryptographic core of the system. It models the quantum channel between Alice (sender) and Bob (receiver). The protocol proceeds through six stages as illustrated in Figure~\ref{fig:bb84-flow}.

In eavesdrop mode, an intermediate Eve chooses random bases independently. When Eve's basis differs from Alice's, the transmitted bit is randomised before Bob measures it, introducing approximately 25\% errors. If the computed error rate exceeds the configured threshold (15\% by default), the receiver rejects the key and blocks the message.

\section{Packet Envelope Design}

Every message is transmitted as a JSON envelope over the raw TCP socket. The envelope schema is as follows:

\begin{itemize}
    \item \textbf{type}: \texttt{"message"} for direct delivery or \texttt{"relay"} for MITM routing.
    \item \textbf{packet}: Contains the AES-encrypted payload (\texttt{iv} and \texttt{ciphertext} in Base64), the BB84-derived key in hexadecimal, a single-use \texttt{nonce}, a \texttt{timestamp}, and the \texttt{route} array.
    \item \textbf{senderName}, \textbf{senderIp}: Identification of the originating machine.
    \item \textbf{attackMode}: One of \texttt{normal}, \texttt{eavesdrop}, \texttt{mitm}, or \texttt{replay}.
    \item \textbf{targetIp}, \textbf{targetPort}: Present only in relay envelopes, specifying the real destination.
\end{itemize}

The response envelope returned by the receiver contains an \texttt{ok} boolean, the decrypted \texttt{plaintext} (on success), \texttt{attackDetected} flag, \texttt{attackType} description, and \texttt{errorRate}.

\section{Attack Detection Design}

Three attack detection mechanisms are layered at the receiver:

\begin{enumerate}
    \item \textbf{Eavesdrop Detection}: After BB84 simulation with the \texttt{eavesdrop} flag, the receiver computes the error rate. Any rate exceeding \texttt{ERROR\_THRESHOLD} (0.15) causes the message to be blocked.
    \item \textbf{MITM Detection}: If the envelope's \texttt{attackMode} field is \texttt{"mitm"} (set by the relay node when forwarding), the receiver immediately flags it as a Man-in-the-Middle attack without needing to check the error rate.
    \item \textbf{Replay Detection}: The receiver maintains a nonce registry with a 60-second TTL. Any envelope whose nonce is already present in the registry is rejected as a replay attack.
\end{enumerate}

\section{Component Interaction and Data Flow}

The complete data flow for a secure message transmission is as follows:

\begin{enumerate}
    \item User types a message and selects a peer and mode in the React dashboard.
    \item The dashboard calls \texttt{POST /api/send-to-peer} on the Flask API with the message, target IP, port, attack mode, and optional relay details.
    \item Flask invokes \texttt{send\_message\_to\_peer()} in \texttt{peer\_socket.py}.
    \item \texttt{establish\_key()} in \texttt{bb84.py} simulates the quantum channel and returns a \texttt{BB84Result} with the derived key and error rate.
    \item \texttt{encrypt\_message()} in \texttt{crypto\_utils.py} encrypts the payload with AES-256-CBC using the derived key.
    \item The encrypted envelope is sent over a raw TCP socket to the target peer's port 5010.
    \item The target's \texttt{\_handle\_client()} thread receives and parses the envelope.
    \item Attack detection checks are performed (error rate, MITM flag, nonce registry).
    \item If all checks pass, \texttt{decrypt\_message()} recovers the plaintext and the message is stored in the inbox.
    \item The response JSON is returned to the sender and displayed in the dashboard.
\end{enumerate}
